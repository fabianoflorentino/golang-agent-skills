# google/wire - Compile-Time Code Generation

Wire turns an explicit provider graph into plain Go constructor calls. Errors surface at build time - if the graph is incomplete or ambiguous, `wire` fails - which means a wiring mistake can never ship. The cost is a codegen step that runs after every dependency change. Docs: [github.com/google/wire](https://github.com/google/wire) and its [guide](https://github.com/google/wire/blob/main/docs/guide.md).

## Providers and sets

Providers are plain constructors. Group them with `wire.NewSet`, and bind interface-to-impl explicitly:

```go
package wire

import "github.com/google/wire"

var InfraSet = wire.NewSet(
    NewConfig,
    NewDatabase,
    NewCache,
)

var ServiceSet = wire.NewSet(
    NewUserService,
    wire.Bind(new(UserStore), new(*PostgresUserStore)),
    wire.Bind(new(Cache), new(*RedisCache)),
)
```

## Injector and build constraint

The injector lives in a `//go:build wireinject` file so it only exists for the tool, and declares what `main` needs:

```go
// wire.go
//go:build wireinject

package main

import "github.com/google/wire"

func InitializeApp() (*App, error) {
    wire.Build(
        InfraSet,
        ServiceSet,
        NewApp,
    )
    return nil, nil // the generated file replaces this body
}
```

Run `wire ./...` to emit `wire_gen.go` - commit it and never hand-edit it; regenerate after each change. It reads like hand-written wiring, which is exactly the point: Wire's output is an ordinary sequence of constructor calls:

```go
// wire_gen.go - generated by wire
func InitializeApp() (*App, error) {
    cfg := NewConfig()
    db, err := NewDatabase(cfg)
    if err != nil {
        return nil, err
    }
    store := NewPostgresUserStore(db)
    cache := NewCache(cfg)
    svc := NewUserService(store, cache)
    return NewApp(svc), nil
}
```

Cleanup functions flow through the return values you already author: constructors that return `(T, func())` give Wire the teardown to chain.

## Testing

There is no container to clone - tests construct services the same way production does:

```go
func TestUserService(t *testing.T) {
    mock := &MockUserStore{...}
    svc := NewUserService(mock, NewTestCache())
    // exercise svc
}
```

## Tradeoffs

- Graph errors caught at compile time.
- Requires running `wire ./...` after dependency changes and keeping generated files in sync.
- Eager construction - no lazy loading, no runtime container.
- No built-in lifecycle management; cleanups via returned `func()` only.
- Interface bindings and provider sets add boilerplate as graphs grow.

Wire injectors must carry `//go:build wireinject`; generated `wire_gen.go` must never be edited by hand.
