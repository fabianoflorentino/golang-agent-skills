# godig sample output

Representative `-o md` captures for every `godig` command, taken against godig v0.2.0. Empty cells render as `—`. Field sets mirror the underlying data sources - pkg.go.dev for most commands, the Go vulnerability database (`vuln.go.dev`, OSV) for `vulns` - so they may grow over time.

## overview

Start here: one call that bundles metadata, recent and latest versions, licenses, and a vuln signal.

`godig overview github.com/samber/ro -o md`

## vulns

Since v0.2.0 `vulns` reads the Go vulnerability database (`vuln.go.dev`, OSV) directly, so `summary` and per-range fix versions are populated (they were empty when sourced from pkg.go.dev). `fixedVersion` is gone - introduced/fixed versions now live in `ranges`; `aliases`, `packages`, and `references` fields are new.

`godig vulns github.com/dgrijalva/jwt-go -o md`

| aliases | details | id | ranges | summary |
| --- | --- | --- | --- | --- |
| ["CVE-2020-26160","GHSA-w73w-5m7g-f7qc"] | If a JWT contains an audience claim with an array of strings ... | GO-2020-0017 | [{"introduced":"0.0.0-20150717181359-44718f8a89b0"}] | Authorization bypass in github.com/dgrijalva/jwt-go |

A module with no known vulnerabilities returns an empty list. Only `--version` and `--limit` apply here - `--filter` and `--module` do not.

## Raw and large outputs

`package doc`, `package examples`, `symbol examples`, and `module readme` return raw Markdown (`-o md` or `-o raw`):

```markdown
# package ro

## Constants

...
```

`package licenses` and `module licenses` return the full license text. These are the outputs to reach for only when you need the whole document - prefer the narrow commands in chat.
